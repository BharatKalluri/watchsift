WatchSift privacy and data

Updated 12 October 2026. This document describes the local prototype. Public hosting and distribution are pending data permission and final publisher/contact details.

Rating lookups

On Netflix and Prime Video, WatchSift reads visible title cards and sends provider names and title IDs, titles, and available release-year text, duration text, explicit movie/series labels, and carousel row labels to its matching API. Rating lookups run in the background. When you open a Netflix detail dialog or Prime Video detail page, WatchSift reads that main title’s year and duration text for the backend to interpret and improve matching. WatchSift never opens or closes dialogs or blocks browsing. WatchSift does not read or send your streaming-service credentials, cookies, profile details, or viewing history. The local development build sends rating requests to your own computer. Public hosting is not yet active.

The extension does not persist rating results, title mappings, or streaming-site year/type metadata. The backend stores shared provider ID to IMDb ID mappings and the submitted title/year/type context for successful OMDb lookups, without user or profile identifiers and without automatic expiry. The backend persists IMDb title metadata, ratings, and vote counts and reuses them for seven days after a successful OMDb fetch. Cached data is shared across providers and users. Expired entries refresh on demand; old rows are preserved if refresh fails. Missing-title results are not cached. The backend sends titles, available year/type hints, and mapped IMDb IDs to OMDb; provider names, streaming-service title IDs, and raw duration/row-label text stay within WatchSift. OMDb receives the backend server’s IP address rather than the browser’s IP address. Reloading a supported site or revealing new cards makes backend lookups, which can reuse this shared cache. Only the state needed to display the current page’s badges is kept in memory.

Lookup contents are used to return IMDb ratings and vote counts and are not stored in request logs. Preferences and connection status/retry deadlines are stored in your browser. The server receives your IP address as part of the network connection and uses it transiently for rate limiting.

Provider selectors are bundled with the extension. The extension does not download selector configuration or send usage counts or missing-rating reports. Updating selectors requires an extension update.

When upgrading from the reporting-enabled prototype, stored sharing preferences, unsent reporting queues, and local report history are cleared. Shared provider-to-IMDb mappings and cached IMDb data are stored in the configured PostgreSQL database. Reporting and remote selector configuration endpoints are no longer supported.

Use and security

Data is used only to provide and improve WatchSift’s rating and filtering features. It is not sold or used for advertising. Production builds require HTTPS. All use of user data is limited to the disclosed purpose, consistent with the Chrome Web Store User Data Policy, including Limited Use requirements.

Public release

Before publication, this policy will identify the publisher, contact channel, hosted API and Railway’s processing and retention practices. OMDb data-use terms must also be checked for the planned release. WatchSift is an independent product and is not affiliated with Netflix, Amazon, or IMDb.
